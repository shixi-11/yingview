# 映窗运营入口

本说明描述从版本就绪到对外发布的运营流程。`scripts/prepare-launch.ps1`只在本机生成发布说明和宣传草稿，不联网、不调用外部AI、不发帖，也不创建计划任务。运行脚本不会证明版本已发布；只有在GitHub Release页面和下载文件都实际公开后，文案链接才可对外使用。

## 触发链

仓库的 **Actions → Prepare release draft → Run workflow** 提供一次触发入口：输入预览版本号后，自动运行检查、分别构建简体中文和英文客户端、生成双语说明并创建未发布的GitHub Release草稿。草稿附带`YingView-zh-CN.exe`与`YingView-en-US.exe`两个下载文件；各自安装包内品牌和界面语言一致。它不会公开发布或向社交平台发送内容；草稿内的客户端和说明仍需审阅。该工作流只允许从main运行，已存在的版本不会被覆盖。创建结果不明时先查看Releases，避免重复操作。

1. **确认版本和下载入口。**确定准备发布的版本号，以及对应GitHub Release页面或其中一个真实发布资产的完整HTTPS链接。链接必须指向`shixi-11/yingview`下与版本一致的Release；资产链接应明确指向用户所需的语言版本。
2. **本地生成文案。**在仓库根目录运行脚本，输出双语版本说明、GitHub简介、中英文设计师社群草稿和中英文X草稿。
3. **逐项人工审核。**检查版本号、功能事实、链接是否公开可用、中文和英文署名是否匹配语言，并确认没有带入价格、未实现功能、客户案例或量化节省承诺。
4. **人工决定对外发布。**按平台实际语境编辑并发布；脚本不保存账号信息，不代替发布，也不表示商店上架。
5. **记录结果并复盘。**记录可取得的触达、链接点击、Release访问与下载数，以及试用者自愿提供的任务反馈。没有实际数据时留空，不以估算填补。

### 运行方式

在PowerShell中从项目根目录运行：

```powershell
& .\scripts\prepare-launch.ps1 `
  -Version 'v0.2.0-preview.1' `
  -DownloadUrl 'https://github.com/shixi-11/yingview/releases/tag/v0.2.0-preview.1'
```

默认输出到`output\launch`。也可使用`-OutputDirectory`指定其他目录。链接只接受该GitHub仓库中与`Version`相同的Release页面，或该版本下以`.msix`、`.exe`、`.msi`结尾的直接下载资产地址。脚本拒绝其他域名、查询参数、片段标识和不匹配版本的链接。再次运行会覆盖同名文案文件。

## 固定产品事实

- 图片按比例完整适配窗口；小图可自动放大，不填满裁切。
- 可收起迷你缩略图栏用于文件夹内浏览。
- 图片删除送入Windows回收站。
- 主题预设可即时预览，支持调整颜色、文字大小和紧凑工具栏。
- 双图比较支持同步缩放和平移，并可切换深色、浅色或棋盘格背景。
- “保留 / 待定”标记及CSV导出预览免费提供。
- 图片留在本机，不会上传。
- Pro购买功能尚未开放；不发布已生效价格或可购买承诺。

超出以上范围的功能、兼容格式、性能数字、独家性、客户评价、节省时间和销量都必须先有可核实证据，不能由模板推断。

## 首批试用与指标

先人工邀请8–12位设计师或创作者进行首轮试用，重点观察透明素材审阅和日常看图是否顺手。试用者自行选择素材；不收集或要求上传图片。参与和反馈均由本人自愿提供，记录只保留完成任务所需的信息。

按实际可取得的数据观察以下转化环节：

- **触达→点击：**各渠道可见触达量与Release链接点击量；若渠道没有可用统计，就记录为未知。
- **访问→下载：**Release访问与下载资产数量；使用平台实际显示的计数，不把下载等同于安装或成功使用。
- **下载→首次完成任务：**通过试用者自愿回报，记录是否成功打开图片、完整查看，以及是否完成透明素材对比；不通过应用遥测推断。
- **首次使用→再次使用：**在约定的回访中询问是否再次打开及原因，保留用户原意，不推算留存率。
- **反馈→继续意愿：**记录最有帮助的功能、阻塞点和是否愿意继续试用；Pro意向与价格接受度仅作研究问题，不表示功能或价格已推出。

首轮重点是确定真实任务能否完成、用户是否愿意再次使用，以及阻塞点集中在哪里，不预设转化目标，也不把少量试用者的反馈写成普遍结论。
